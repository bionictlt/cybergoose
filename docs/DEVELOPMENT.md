# Разработка Cybergoose

## Окружение и сборка

Нужны macOS, Swift 6 / Xcode Command Line Tools и Homebrew-зависимости:

```sh
brew install libssh2 openssl@3
./scripts/build-app.sh
open dist/Cybergoose.app
```

`Package.swift` можно открыть в Xcode. Пути зависимостей переопределяются
через `CYBERGOOSE_SSH2_PREFIX` и `CYBERGOOSE_OPENSSL_PREFIX`.

Swift-код рассчитан на macOS 14. Сборщик вычисляет фактический минимум
вложенных библиотек и записывает его в Info.plist. Текущий готовый артефакт —
arm64 / macOS 26+: используемая сборка OpenSSL требует macOS 26.
Поддержка macOS 14 готовым приложением пока не подтверждена.

`.app` включает libssh2, OpenSSL, их лицензии и локальную ad-hoc подпись.
Для запуска готового `.app` Homebrew не нужен. Developer ID и notarization
пока не настроены.

## Структура

| Каталог | Назначение |
|---|---|
| `Sources/Cybergoose/App` | SwiftUI App и команды приложения |
| `Sources/Cybergoose/UI` | Панели, таблица AppKit, формы и Quick Look |
| `Sources/Cybergoose/Models` | Состояние окна, панели, профили и метаданные |
| `Sources/Cybergoose/Connections` | SSH, FTP/FTPS, S3 и общий RemoteConnection |
| `Sources/Cybergoose/Operations` | Очередь, передача, отмена, удалённый редактор |
| `Sources/Cybergoose/Persistence` | Закладки |
| `Sources/Cybergoose/Security` | Keychain и доверенные SSH host keys |
| `Sources/CSSHBridge` | C-мост к libssh2 |
| `Sources/CCurlBridge` | C-мост к системной libcurl |
| `Tests` | Автономные и серверные проверки |

Сетевые C-вызовы выполняются вне MainActor на последовательных очередях.
UI использует общий интерфейс `FileSystem`, файловые операции —
`RemoteConnection`. Локальное дисковое IO также вынесено с главного потока.

## Протоколы

### SFTP и SCP

Поддерживаются пароль и SSH-ключ с passphrase. До авторизации проверяется
host key: неизвестный fingerprint требует решения пользователя,
изменившийся ключ блокирует подключение.

SCP используется для передачи содержимого файлов. Просмотр каталогов,
метаданные и файловые команды используют SFTP на том же сервере;
SCP-only сервер без SFTP пока не поддерживается.

Одна SSH-сессия используется для навигации и передачи, поэтому запрос
каталога может ждать окончания другого сетевого вызова. TCP connect и
блокирующие вызовы libssh2 имеют таймаут 15 секунд. DNS использует системный
resolver и может завершиться позже отмены; его устаревший результат не
публикуется в UI. Отмена подключения закрывает сокет, а C-handles
освобождаются после завершения текущих вызовов.

### FTP и FTPS

FTP: порт 21. Explicit FTPS: порт 21. Implicit FTPS: порт 990.
Для FTPS обязателен TLS командного канала и канала данных, с проверкой
сертификата. Переход на незашифрованное соединение автоматически не выполняется.
Кнопка гостевых реквизитов заполняет `anonymous` / `anonymous@`.

Используются пассивные соединения, абсолютные пути от `/`, MLSD и fallback
на Unix LIST. Неизвестные форматы LIST и кодировки, отличные от UTF-8,
завершаются ошибкой. Unix LIST пока не даёт времени изменения в модели:
внешняя правка с сохранением размера может остаться незамеченной.

FTP не предоставляет атомарного условного rename. Клиент повторно проверяет
назначение и использует RNFR/RNTO без предварительного удаления старого файла,
но полностью исключить гонку с другим клиентом нельзя. POSIX-права через
FTP не переносятся.

### S3

Поля: HTTPS endpoint без схемы и bucket, Access Key ID, Secret Access Key,
bucket, регион и необязательный Session Token. Поддерживаются path-style
и virtual-hosted style; начальный путь `/` открывает bucket, `/backups` — префикс.
Подпись Signature V4 формирует libcurl, SHA-256 тела вычисляет CryptoKit.

Списки читаются с пагинацией. Замена использует `If-Match` с ETag,
создание — `If-None-Match: *`, удаление исходного объекта — условие ETag.
Совместимый сервис должен поддерживать эти условия.

Для условной замены/переименования объект скачивается в приватный дисковый кеш,
затем отправляется в назначение и удаляется из исходного пути после проверки.
Это требует дополнительного трафика и места на Mac. Content-Type и
пользовательские метаданные сохраняются; ACL и история версий не переносятся.

Пока отсутствуют multipart upload, переименование каталогов-префиксов,
управление bucket и версиями. Загрузка/переименование ограничены 5 GiB;
скачивание этим порогом не ограничено. Ключи с сегментами `.`/`..`, пустыми
сегментами, управляющими символами или совпадающими именами объекта и
каталога не поддерживаются и не преобразуются в другие ключи автоматически.

## Очередь и редактор

F5 и drag-and-drop копируют, F6 перемещает. Каталоги обходятся рекурсивно
без следования символическим ссылкам. Конфликты файлов поддерживают замену,
замену всех в группе, пропуск и отмену. Строка `..` является навигацией
и исключена из файловых операций.

Передача использует уникальный `.cybergoose-UUID.part`. Источник перемещения
удаляется после проверки результата и повторной проверки исходных метаданных.
При обрыве на сервере может остаться `.part`; очистка по уже закрытому
соединению не гарантируется. Очередь пока не восстанавливается после выхода.

Удалённое редактирование создаёт приватную локальную копию и наблюдает
её каталог, обнаруживая в том числе атомарное сохранение заменой inode.
Изменения сравниваются по SHA-256, снимки отправляются через очередь.
Изменение удалённых метаданных вызывает конфликт; размер и mtime не являются
криптографической проверкой удалённой версии.

При ошибке или отключении рабочая копия и неотправленные снимки сохраняются.
После подключения к исходному серверу можно повторить задание. Автоматическое
восстановление редакторских сеансов после перезапуска пока отсутствует.

## Хранилища

Каталог сохраняет прежнее написание имени для совместимости.
В `~/Library/Application Support/CyberGoose/` находятся:

- `connections.json` — закладки без секретов;
- `known-hosts.json` — доверенные публичные SSH-ключи по хосту и порту;
- `Editing/` — рабочие копии и снимки удалённого редактора.

Каталог создаётся с правами 0700, хранилища — 0600. Секреты сохраняются в
login Keychain только при включённом флажке. S3 Secret Key и Session Token
хранятся вместе в одном элементе Keychain. Ошибка хранилища доверия не
сбрасывает доверенные ключи автоматически. Импорт `~/.ssh/known_hosts`
пока не реализован.

## Проверки

```sh
./scripts/check.sh
./scripts/check-sftp.sh
./scripts/check-operations.sh
./scripts/check-protocols.sh
./scripts/check-drag-drop.sh
./scripts/check-keychain.sh
```

Автономные проверки покрывают локальные каталоги, закладки, SSH trust store,
пути, очередь и конфликты, сохранность источника, редакторские сохранения,
FTP MLSD/LIST и S3 на подставном транспорте. Drag-and-drop проверяется через
модель и настоящие обработчики AppKit `validateDrop`/`acceptDrop` с тестовым
NSDraggingInfo. Также проверяются Tab, строка `..` и её исключение из операций.

Эти проверки не заменяют настоящий TLS/SSH handshake и серверную проверку
подписи S3. Сквозные проверки всех протоколов пока не завершены. В среде
разработки sandbox запрещал bind на localhost, а CLI-проверка Keychain
возвращала ошибку -50. Успешную работу Keychain нужно подтвердить в обычном
сеансе macOS.

Для отдельного тестового сервера:

```sh
CG_TEST_PROTOCOL=sftp \
CG_TEST_HOST=test.example.com \
CG_TEST_USER=tester \
CG_TEST_DIRECTORY=/disposable-tests \
CG_TEST_KEY=/absolute/path/to/test-key \
CG_TEST_FINGERPRINT='SHA256:verified-fingerprint' \
./scripts/check-remote.sh
```

Скрипт создаёт собственную UUID-папку, проверяет загрузку, отказ перезаписи,
Unicode-имена, переименование, побайтовое скачивание и удаляет свои объекты.
Для теста используйте специально выделенный каталог или bucket.

`CG_TEST_PROTOCOL`: `sftp`, `scp`, `ftp`, `ftps`, `ftpsImplicit`, `s3`.
Дополнительные параметры: `CG_TEST_PORT`, `CG_TEST_SECRET` (пароль/passphrase
или S3 Secret Key), `CG_TEST_BUCKET`, `CG_TEST_REGION`,
`CG_TEST_SESSION_TOKEN`, `CG_TEST_VIRTUAL_HOSTED=1`. Fingerprint для SSH
сверяется до отправки credentials.

## Сборка приложения

```sh
./scripts/build-app.sh
```

Готовое приложение создаётся в `dist/Cybergoose.app`. Результаты сборки и кэши
не включаются в Git. Иконка приложения берётся из `Icon.png`.
Готовые выпуски распространяются через GitHub Releases.
